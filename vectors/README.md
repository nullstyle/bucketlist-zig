# Reproducible version-one vectors

`reference.json` and `reference.zig` are generated by `tools/reference.py`, an
independent Python model. It does not import Zig code or execute the library.
Run `mise exec -- python tools/reference.py` to regenerate and add `--check`
to verify exact reproducibility without rewriting files.

The corpus contains four profiles (depths 1, 2, 3, and production 11), 128
advances each, a signed-key/two-table schema, and every referenced canonical
bucket's complete bytes and hash. It exercises empty advances, updates,
absent deletes, unchanged puts, call-order coalescing, delete/recreate,
signed extrema, maximum unsigned values, empty bounded keys, zero bytes,
common prefixes, and terminal deletion compaction. Each advance records the
normalized input bucket, full current/snapshot/pending topology, list root,
continuation hash, and outer database commitment.

`src/vectors_test.zig` compares typed database operations and raw engine inputs
with this corpus. It resumes checkpoints before and at spill boundaries and
checks the remaining independently generated trace. The generated Zig module
is a normal build dependency so changing fixtures invalidates compilation.
The aggregate hash is SHA-256 of every database commitment from genesis through
advance 128, concatenated in sequence order. The native/WASM runner checks that
aggregate while exercising the same typed operations and checkpoint recovery.

The separate raw-bucket literals in `src/list.zig` check the first geometric
boundaries against a distinct simple insert-only trace. The reference schedule
was derived from pinned Core source; this is a model of this project's format,
not a claim of Stellar byte/hash compatibility.
